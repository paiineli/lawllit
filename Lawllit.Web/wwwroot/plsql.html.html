por quê

função no SYSDATEnunca na coluna: TRUNC(HIREDATE) mataria o índice → full scan. coluna crua = índice vivo (sargability).

formulário · questão 7Criar uma function que receba um id do funcionário e retorne o salario dele ou -1 caso o funcionário não seja cadastrado;

sua resposta

CREATE OR REPLACE FUNCTION FN_SALARIO_FUNCIONARIO(P_ID_FUNCIONARIO IN EMP.EMPNO%TYPE)
  RETURN EMP.SAL%TYPE
IS
  V_SALARIO EMP.SAL%TYPE;
BEGIN
  SELECT E.SAL
    INTO V_SALARIO
    FROM EMP E
   WHERE 1 = 1
     AND E.EMPNO = P_ID_FUNCIONARIO;

  RETURN V_SALARIO;
EXCEPTION
  WHEN NO_DATA_FOUND THEN
    RETURN -1;
END FN_SALARIO_FUNCIONARIO;
/

formulário · questão 8Criar uma function que receba como parâmetro um cargo e retorne o id do funcionário de maior salário. Caso tenha mais de um, retorne o com data de contratação mais recente;

sua resposta

CREATE OR REPLACE FUNCTION FN_MAIOR_SALARIO_POR_CARGO(P_CARGO IN EMP.JOB%TYPE)
  RETURN EMP.EMPNO%TYPE
IS
  V_ID_FUNCIONARIO EMP.EMPNO%TYPE;
BEGIN
  SELECT X.EMPNO
    INTO V_ID_FUNCIONARIO
    FROM (SELECT E.EMPNO
            FROM EMP E
           WHERE 1 = 1
             AND E.JOB = P_CARGO
           ORDER BY E.SAL DESC,
                    E.HIREDATE DESC) X   -- 1º ordena DENTRO
   WHERE 1 = 1
     AND ROWNUM = 1;                     -- 2º corta FORA

  RETURN V_ID_FUNCIONARIO;
EXCEPTION
  WHEN NO_DATA_FOUND THEN
    RETURN NULL;
END FN_MAIOR_SALARIO_POR_CARGO;
/

✗ errado — tudo junto

rownum é atribuído ANTES do order by → pega uma linha qualquer e só depois ordena
✓ certo — ordena dentro, corta fora

  SELECT EMPNO FROM EMP

formulário · questão 9Criar uma procedure que receba uma cidade como parâmetro e chame DBMS_OUTPUT.PUT_LINE, passando como parâmetro as informações de: id do funcionário, cargo e salario de cada funcionário que trabalha naquela cidade ou "nenhum funcionário encontrado" caso não encontre nenhum.

CREATE OR REPLACE PROCEDURE PR_FUNCIONARIOS_POR_CIDADE(P_CIDADE IN DEPT.LOC%TYPE)
IS
  V_ENCONTROU BOOLEAN := FALSE;
BEGIN
  FOR R IN (SELECT E.EMPNO ID_FUNCIONARIO,
                   E.JOB CARGO,
                   E.SAL SALARIO
              FROM EMP  E,
                   DEPT D
             WHERE 1 = 1
               AND E.DEPTNO = D.DEPTNO
               AND UPPER(D.LOC) = UPPER(P_CIDADE)
             ORDER BY E.EMPNO)
  LOOP
    V_ENCONTROU := TRUE;
    DBMS_OUTPUT.PUT_LINE('ID_FUNCIONARIO: ' || R.ID_FUNCIONARIO ||
                         ' | CARGO: ' || R.CARGO ||
                         ' | SALARIO: ' || R.SALARIO);
  END LOOP;

  IF NOT V_ENCONTROU THEN
    DBMS_OUTPUT.PUT_LINE('nenhum funcionário encontrado');
  END IF;
END PR_FUNCIONARIOS_POR_CIDADE;

formulário · questão 10Acrescentar uma coluna na tabela EMP, defina oportunamente o tipo da coluna e encontre uma solução para que todas as vezes que um funcionário receba um aumento, nessa nova coluna seja registrada a quantia do último aumento recebido;

sua resposta

ALTER TABLE EMP ADD (VL_ULTIMO_AUMENTO NUMBER(7,2));

CREATE OR REPLACE TRIGGER TRG_EMP_ULTIMO_AUMENTO
  BEFORE UPDATE OF SAL ON EMP
  FOR EACH ROW
  WHEN (NEW.SAL > OLD.SAL)          -- SEM dois-pontos no WHEN
BEGIN
  :NEW.VL_ULTIMO_AUMENTO := :NEW.SAL - :OLD.SAL;  -- COM dois-pontos no corpo
END TRG_EMP_ULTIMO_AUMENTO;
/

o fluxo da trigger

UPDATE ... SET SALcom OF SAL: só dispara se mexer em SAL
→
WHEN new > old?não (redução/nulo) → grava sem tocar na coluna
→

before vs after — a tabela mutante

✓ BEFORE (a sua)
atribui :NEW direto — o valor entra na própria gravação da linha. sem truque, sem erro.
✗ AFTER + UPDATE EMP

por quê

NUMBER(7,2)o aumento é diferença entre dois salários → mesmo domínio de SAL (máx 99999.99). é a resposta ao "defina oportunamente o tipo".
null no WHENNULL > 800 = desconhecido → não dispara. coerente com a lógica de 3 valores; se o requisito quisesse capturar, entraria NVL — decisão de requisito. teste no ex 9.
sem commit dentrotrigger vive na transação do comando. rollback do update desfaz o que ela gravou junto.
"e se o UPDATE afetar 14 linhas?"FOR EACH ROW = dispara 14 vezes, uma por linha, cada uma com seu :NEW/:OLD. sem o FOR EACH ROW seria 1 vez por comando, sem ver linha nenhuma.

EX7function do zero: qtd por cidade dom

FN_QTD_FUNCIONARIOS_CIDADE(P) → chicago 6 · boston 0 · sorocaba 0. com COUNT não precisa exceção — por quê?

solução
CREATE OR REPLACE FUNCTION FN_QTD_FUNCIONARIOS_CIDADE(P_CIDADE IN DEPT.LOC%TYPE)
  RETURN NUMBER IS
  V_QTD NUMBER;
BEGIN
  SELECT COUNT(*) INTO V_QTD
    FROM EMP E, DEPT D
   WHERE E.DEPTNO = D.DEPTNO
     AND UPPER(D.LOC) = UPPER(P_CIDADE);
  RETURN V_QTD;
END;
/

COUNT sempre devolve 1 linha (nem que seja 0) — o INTO nunca dispara no_data_found aqui. saber quando a exceção não é necessária vale tanto quanto usá-la.

EX8q9 com cursor explícito dom

mesmo comportamento, controle manual. depois diga em voz alta por que preferiu o implícito.

solução
CREATE OR REPLACE PROCEDURE PR_EXPL(P_CIDADE IN DEPT.LOC%TYPE) IS
  CURSOR C IS
    SELECT E.EMPNO, E.JOB, E.SAL
      FROM EMP E, DEPT D
     WHERE E.DEPTNO = D.DEPTNO
       AND UPPER(D.LOC) = UPPER(P_CIDADE);
  R C%ROWTYPE;
BEGIN
  OPEN C;
  LOOP
    FETCH C INTO R;
    EXIT WHEN C%NOTFOUND;
    DBMS_OUTPUT.PUT_LINE(R.EMPNO || ' | ' || R.JOB || ' | ' || R.SAL);
  END LOOP;
  IF C%ROWCOUNT = 0 THEN
    DBMS_OUTPUT.PUT_LINE('nenhum funcionário encontrado');
  END IF;
  CLOSE C;
END;
/

%ROWCOUNT substitui a flag; CLOSE obrigatório. mais código, mais pontos de falha — a defesa do implícito se escreve sozinha.
